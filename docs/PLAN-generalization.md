# 일반화 계획 — 다른 사람도 쓸 수 있게 (2026-10-06, 레드팀 반영)

상태: **레드팀 처분을 반영했다. 순서는 맨 아래 「고친 순서」가 정본이다**(본문의 「순서」 절은 레드팀 전의 안으로 남긴다). 다음 터미널을 무엇으로 할지는 대상 사용자가 정해져야 정할 수 있어 요한님께 묻는다. 공개·배포는 요한님 승인 사항이라 이 문서로 실행하지 않는다.

## 지금 (사실만)

- 지원: 터미널 2종(Ghostty · Orca) × 에이전트 2종(claude · codex). 맥 전용, SwiftPM, 테스트 86개.
- 문구가 전부 한국어로 코드에 박혀 있다(알림·메뉴·편집 화면·오류). 핵심 모듈의 오류도 한국어 문장이다.
- 터미널과 에이전트는 `enum` + `switch` 로 갈린다(`TerminalHost`, `Agent`). 「터미널」(맨 앞 세션 찾기 · 글자 쓰기 · 화면 읽기 · 화면 지연)과 「에이전트」(입력창 판정 · 전환 단계 · 결과 문구)는 코드에서 이미 서로를 모른다.
- 프리셋 파일은 에이전트 이름이 필드로 고정돼 있다(`{"claude": {...}, "codex": {...}}`).
- 화면 문구에 기댄다: claude `Select model` · `s to use this session only` · `Set model to` · `Switch model?`, codex `Select Model and Effort` · `Select Reasoning Level` · `s session` · `Model changed to`. claude 2.1.283·2.1.288(읽기만)·2.1.289·2.1.291, codex 0.156.0·0.160.0·0.160.1 에서 확인.
- 터미널별 실측: Orca 는 앱 소켓으로 읽기 0.5ms · 쓰기 1ms(비공개 통로, 인증 값을 파일에서 읽는다). Ghostty 는 화면 글자를 0.5초 보관해 검증 한 단계가 0.5초다. Orca 는 「지금 보이는 탭」이 1.5~2.5초 늦다.
- 서명은 Apple Development 인증서. 공증·Developer ID 는 해 본 적 없다.
- 다른 터미널(iTerm2 · Terminal.app · tmux · kitty · WezTerm · VS Code)과 다른 에이전트(gemini · cursor-agent 등)는 **하나도 실측하지 않았다.**

## 목표와 비목표

- 목표: 요한님 환경 밖의 사람이 설치해서, 자기 터미널·에이전트에서, 자기 언어로 쓸 수 있다. 지금의 안전 조건(입력창이 보일 때만 보낸다 · 낡은 화면으로 판단하지 않는다 · 읽는 곳과 쓰는 곳이 같다)은 그대로다.
- 비목표: 리눅스·윈도우, 에이전트의 다른 설정(권한 모드 등) 전환, 원격 세션.

## 설계

### 1. 끼워 넣는 자리 두 개

```
TerminalDriver                      AgentDriver
  bundleIDs                           id ("claude")
  frontSession() -> Session?          detect(session) -> Bool        프로세스·제목·화면
  write(bytes, to:)                   inputVisible(screen) -> Bool
  snapshot(of:) -> 화면(+초안)         plan(preset, 설정) -> [Step]    + 대안 단계
  screenLagMs                         stepEffortPlan(up) -> [Step]
  processHint(session) -> pid/tty?    summarize(결과 줄들) -> 알림 제목
                                      launchCommand(preset) -> [String]
```

- `Step` 과 `Runner` 는 공용이다. 지금 `Runner` 안에 섞여 있는 claude 전용 판정(결과 줄 · 확인 창 · effort 줄)과 codex 전용 판정(선택창 머리말)은 각 `AgentDriver` 가 내놓는 「화면 판정 함수」로 옮긴다 — `Step` 은 그 함수를 이름으로 부른다.
- 등록은 코드 안의 배열 하나. 플러그인 적재(외부 번들·스크립트)는 하지 않는다.

### 2. 터미널을 늘리는 순서 — 재고 나서 정한다

터미널마다 반나절짜리 실측을 먼저 한다. 표를 채운 뒤에 순서를 정한다.

| | 맨 앞 세션을 안다 | 바이트를 쓴다 | 화면을 «지금 것으로» 읽는다 | 권한 |
|---|---|---|---|---|
| tmux(어느 터미널 앱이든) | `list-clients` 의 최근 활동 클라이언트 → 활성 pane (후보) | `send-keys -l`/`-H` (후보) | `capture-pane -p` (후보) | 없음(후보) |
| iTerm2 | AppleScript `current session` (후보) | `write text`(줄바꿈 붙음 — 확인 필요) | `contents` (후보) | 자동화 |
| kitty · WezTerm | 원격 제어 CLI (설정을 켜야 함 — 후보) | `send-text` (후보) | `get-text` (후보) | 없음(후보) |
| Terminal.app | AppleScript (후보) | `do script` 는 줄 단위 — 바이트 쓰기 가능 여부 미확인 | `contents`/`history` (후보) | 자동화 |
| VS Code · Cursor 내장 터미널 | 확장이 필요(후보) | 확장 | 확장 | — |

제안하는 첫 대상은 **tmux**: 터미널 앱과 무관하게 한 번에 넓게 덮고, 화면을 지연 없이 읽을 가능성이 가장 높고, 맥 권한이 필요 없다. 단 「맨 앞 창에 붙은 tmux 클라이언트」를 가리는 방법은 실측 전이다.

### 3. 에이전트를 늘리는 조건

새 에이전트는 실제 화면 표본(입력창 · 선택창 · 확인 창 · 결과)과 흉내기(테스트용)가 있을 때만 넣는다. 「세션만 바꾸는」 확정 수단이 없는 에이전트는 기본값을 바꾸는 방식을 쓰지 않고 지원하지 않는다고 말한다.

### 4. 버전이 바뀌면

- 드라이버마다 「확인한 버전 범위」를 갖고, `doctor` 가 설치된 버전과 대조해 범위 밖이면 알린다(막지는 않는다 — 판정은 화면으로 한다).
- 화면이 기대와 다르면 지금처럼 멈춘다. 멈춘 화면의 마지막 몇 줄을 기록 파일에 남겨(사용자 글은 가리고) 고칠 근거로 쓴다.

### 5. 언어

- `Localizable.strings`, 영어가 기준(`defaultLocalization: "en"`), OS 언어로 자동 선택 — candlelight 와 같은 방식.
- 핵심 모듈의 오류는 「종류 + 값」(예: `.inputNotVisible(agent)`)으로 바꾸고 문장은 보여 주는 쪽에서 만든다. 테스트는 문장이 아니라 종류를 본다.
- 1차: 영어 + 한국어. 나머지 7개(일본어 · 중국어 간체 · 번체 · 스페인어 · 프랑스어 · 독일어 · 포르투갈어)는 문구가 굳은 뒤(공개 직전) 한 번에.
- 에이전트 화면의 영어 문구(`Select model` 등)는 번역 대상이 아니다 — 그 도구들의 화면이다.

### 6. 프리셋 파일

`{"agents": {"claude": {...}, "codex": {...}}}` 로 바꾸고 `version: 2`. 옛 형식(`version: 1`)은 읽을 때 올린다(저장은 새 형식).

### 7. 배포 (승인 뒤)

Developer ID 서명 + 공증 → GitHub 릴리스의 zip → 자체 Homebrew tap 의 cask. 자동 업데이트는 cask 에 맡기고 앱 안에는 넣지 않는다(네트워크 코드를 넣지 않는다).

## 순서

1. 자리 나누기(1절) — 동작 변화 없음, 지금 테스트가 그대로 통과해야 한다.
2. 오류를 종류로 바꾸고 문구를 `Localizable.strings` 로(영어 · 한국어).
3. 프리셋 파일 v2.
4. tmux 실측 → 표 → 되면 tmux 드라이버.
5. iTerm2 실측 → 드라이버.
6. 버전 대조(`doctor`).
7. (승인 뒤) 나머지 언어, 서명·공증, cask.

| # | 결정 | 왜 틀릴 수 있나 | 처분 |
|---|---|---|---|
| 1 | 화면 문구에 기대는 선택창 조작을 «남에게 주는» 제품의 중심에 둔다 | claude·codex 가 문구를 바꾸면 모든 사용자가 한꺼번에 멈춘다. 우리는 그 도구들의 출시 일정을 모른다 | **채택(조건부)** — 대안이 없다: codex 는 명령이 없고(선택창뿐), claude 의 명령은 기본값을 바꾼다. 멈출 때 엉뚱한 키를 보내지 않는 것은 86개 테스트와 실측으로 확인했다. 조건: 4절(버전 대조 · 멈춘 화면 기록)을 공개 전에 넣는다 |
| 2 | 다음 터미널을 tmux 로 | 근거가 「넓게 덮을 것 같다」뿐이다. 누가 쓸지 모르고, 맨 앞 클라이언트를 가릴 수 있는지도 모른다 | **보류** — 순서 4의 실측이 끝나기 전에는 정하지 않는다. 대상 사용자가 누구인지는 요한님께 묻는다 |
| 3 | 9개 언어 | 외부 사용자가 한 명도 없는데 문구 하나를 바꿀 때마다 9번 고친다. 기계 번역의 품질을 검증할 사람이 없다 | **채택(단계 나눔)** — 틀(영어 기준 · 자동 선택)과 영어·한국어는 지금, 나머지 7개는 공개 직전 한 번. 요한님 지시(«candlelight 처럼»)는 틀로 충족한다 |

### 2026-10-11 — 3번(언어)의 처분을 고친다

요한님이 「9가지 언어 지원하고 시스템 설정된 언어 자동으로 채택되게 할까? … 더 많은 언어 자동으로도 되나」 라고 물었다(앱 화면 개편 요청과 함께).

- **틀을 넣었다**: 영어가 기준, 시스템 언어 순서로 자동 선택, 번역은 `Resources/<언어>.lproj`. 5절의 «오류를 종류 + 값으로» 는 하지 않았다 — 영어 문장을 키로 쓰는 쪽(`loc("…")`)이 고칠 곳이 훨씬 적고, 문장이 코드에 그대로 보이며, 번역이 없으면 영어로 떨어진다. 테스트가 «문장이 아니라 종류를 본다» 는 목표는 «테스트는 한국어 번역표를 켜고 지금의 한국어 문장을 그대로 본다» 로 대신한다(핵심 문구를 옮길 때).
- **«나머지 7개는 공개 직전»** 은 «이번 화면 개편이 끝나 문구가 굳은 뒤 한 번에» 로 당긴다. 근거가 바뀌었다: 문장을 바꿀 때마다 9번 고치는 비용은 테스트(빠진 번역·다른 자리표를 잡는다)와 기계 번역으로 작아졌다. 남는 약점 — 원어민 검수가 없다 — 은 그대로이고, 문서에 그렇게 적는다.
- **9개의 구성**은 tab-rest 와 같게 한다: 영어 · 한국어 · 일본어 · 중국어(간체) · 스페인어 · 프랑스어 · 독일어 · 포르투갈어 · 아랍어. 5절에 적었던 번체 중국어는 빠지고 아랍어(오른쪽에서 왼쪽)가 들어온다.
- **«더 많은 언어가 자동으로 되나»**: 맥은 번역하지 않는다 — 앱이 가진 언어 가운데서 고를 뿐이다. 언어 하나는 파일 하나라 늘리기는 쉽다(테스트가 빠진 문장을 잡는다).
